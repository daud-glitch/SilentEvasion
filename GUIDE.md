## 🚀 Phase 0: Fresh Runtime Bootstrap (Colab — run once per runtime)

A new Colab runtime has **no project files**. Instead of re-uploading a zip and
discovering halfway through a run that `src/analyze_baseline.py` is missing, run
one cell that restores everything.

Paste the whole of **[colab_bootstrap.py](colab_bootstrap.py)** into a single
Colab cell and run it (or `%run /content/colab_bootstrap.py` if the file is
already there). It writes the sources, downloads the datasets only if they are
missing, and rebuilds the frozen splits:

```
[files] wrote 12 files
[deps] pandas/numpy/sklearn/requests/tqdm + server stack present
[data] processed datasets present, reusing them
[splits] eval_subset.csv        n=800  a0592a3eec60e102  OK
[splits] attack_ch1_input.csv   n=200  48198ef41a629adf  OK
BOOTSTRAP OK: 12 files, data=ready, splits=verified
```

What it does:
1. Writes every `src/*.py` and `tests/*.py`, verifying sha256 per file.
2. Byte-compiles them, so a truncated copy fails immediately instead of at
   sample 300 of a run.
3. Downloads + curates the datasets **only if** `data/processed/` is missing.
4. Rebuilds `results/eval_subset.csv` and `results/attack_ch1_input.csv` and
   compares their fingerprints with the splits every earlier result used.

**`BOOTSTRAP OK` is a precondition, not a nicety.** `DRIFT` means the data on
that runtime produces different splits than the frozen ones — numbers from it
are not comparable with earlier runs, so fix the data before measuring.

Switches: `SLM_ROOT=/content` (project root), `SLM_SKIP_DATA=1` (code only).

### The easier route: the runbook notebook
Instead of pasting the bootstrap by hand, upload **`colab_runbook.ipynb`** — it

baseline → gate → tables), already in order, with the screenshot markers for the


### Regenerating the cell after a code change
`colab_bootstrap.py` is a **copy** of the sources, not a link to them. After


## 📦 Phase 1: Clean Baseline (Estimated time: 10–15 min on free Colab T4)

**Goal:** Measure each SLM's zero-shot F1 before any attack. This is your sanity check.

### Step 1.1: Prepare the balanced evaluation set
```powershell
cd slm_robustness
./venv/Scripts/python.exe src/build_splits.py
```
Writes both frozen inputs (800-row `eval_subset.csv`, 200-row
`attack_ch1_input.csv`) and prints a fingerprint for each. The bootstrap cell
already does this on Colab; re-run it locally whenever `data/processed/` changes.

### Step 1.2: Launch a local LLM server (Ollama or LM Studio)
- **Ollama:** Install from https://ollama.ai, start service: `ollama serve`
- **LM Studio:** Download & launch, load a 3B model (Llama-3.2-3B, Qwen2.5-3B)

### Step 1.3: Run the baseline for ONE model
```powershell
# Example: Qwen2.5-3B via Ollama's open‑api compat endpoint
./venv/Scripts/python.exe src/run_baseline.py \
  --model qwen2.5-3b \
  --base-url http://localhost:11434/v1 \
  --limit 400   # 200 benign + 200 malicious — keeps it under 15 min
```

### Step 1.4: Check the output
Result file: `results/clean_baseline_results.csv`
```powershell
cat results/clean_baseline_results.csv | head -15
```
Expected format per row: `id, task, ground_truth, pred, raw, error, model, task, ...`

### Step 1.5: Summarise F1 per model+task
```powershell
./venv/Scripts/python.exe -c "
import pandas as pd; from src.common import binary_metrics
df = pd.read_csv('results/clean_baseline_results.csv')
for (m,t), g in df.groupby(['model','task']):
    m = binary_metrics(g.ground_truth, g.pred)
    print(f'{m}  |  model={m}, task={t}')
```
**Target sanity threshold:** F1 ≥ 0.70 on both tasks. If a model falls far below, investigate but **do not** tweak the prompt — the point is to measure baseline fragility.

### Step 1.6: Run against the Colab shim
`run_baseline.py` appends `/chat/completions` to `--base-url`, so the URL **must** end in `/v1`:
```bash
# Colab / local shim (CORRECT)
python src/run_baseline.py --model qwen2.5-3b --base-url http://localhost:8000/v1 --limit 40

# WRONG - posts /chat/completions at the root, gets 404 on every sample
python src/run_baseline.py --model qwen2.5-3b --base-url http://localhost:8000
```

**Reading the output:** if `n_unparsed == n` (or equals `--limit`), no model verdict ever reached
`parse_verdict`. That is a plumbing failure, **not** a research result. Check, in order:
1. `--base-url` ends in `/v1` (404s land silently in the `error` column).
2. `error` / `raw` columns are empty and non-empty respectively in the results CSV.
3. The shim is up: `curl http://localhost:8000/health` shows `"mode": "real"` and `"torch": "yes"`.

A run that finishes suspiciously fast (hundreds of `it/s`) is almost always a 404, not inference.

### Step 1.7: Run all 4 models
Point `--base-url` at your endpoint (Colab, Ollama, vLLM) and re-run with `--model all`. The script is designed to be swappable.

## 🎯 Phase 2: Attack Engine 1 — Character‑Level (Typo / Homoglyph)

**Goal:** Generate minimal‑edit adversarial examples that flip the verdict.

### Step 2.1: Build the attack-eligible set (the denominator)

ASR is only defined on messages the CLEAN model actually called malicious.
Attacking the 200 malicious rows of `attack_ch1_input.csv` blindly measures
nothing: the attack cannot "flip" a verdict that was already benign, and the
denominator is then wrong in the paper.

```powershell
cd slm_robustness
./venv/Scripts/python.exe src/build_attack_set.py --all-models
```

This joins each caught row to its text from `results/eval_subset.csv` (the
baseline CSV is deliberately text‑free) and writes:

- `results/attack_eligible.csv` — every model × task, the file the runner consumes
- `results/attack_eligible_<model>_<task>.csv` — one file per pair

It prints the **detection rate** (caught / malicious). That number must be
quoted next to every ASR, e.g. "phi3.5‑mini catches 60% of malicious emails,
of which 42% flip under a 15% character budget". An ASR without its catch rate
is not interpretable.

### Step 2.2: Run the character‑level attack
```powershell
./venv/Scripts/python.exe src/run_attack.py --model qwen2.5-3b --mode char --attempts 3
```

`src/attack_common.py` does the work, and every rule in it exists to keep the
number honest:

- the **original text is re-queried** (`orig_pred`), never assumed malicious;
- the prompt is `build_messages(task, ...)` — the same one the baseline used,
  and the sample's own task, so an email is not scored with the SMS prompt;
- a success is strictly `orig_pred == 1 → pert_pred == 0`;
- edits are the **exact Levenshtein distance**, not estimated from
  `len(text) * 0.15` (and not a `difflib` opcode tally, which is not minimal);
- **one** edit budget per sample (15%), shared by all four operations — the
  earlier version gave each operation its own budget and reached ~22%, which
  made the "imperceptible" claim false;
- similarity is **word‑set Jaccard**, reported under that name. This repo does
  not ship a semantic-similarity model, so there is no BERTScore here.

**Output:** `results/attack_results_char_<model>.csv` with columns
`id, mode, task, orig_pred, pert_pred, success, counted, skip_reason,
perturbed_text, attack_types, similarity, edits, subs, dels, ins,
perturbation_rate`, plus `results/asr_summary_char_<model>.txt`.

### Step 2.3: Read the ASR correctly
```powershell
./venv/Scripts/python.exe -c "
import pandas as pd
df = pd.read_csv('results/attack_results_char_qwen2.5-3b.csv')
c = df[df.counted == True]          # only rows actually attacked
print('attacked :', len(c))
print('flips    :', int(c.success.sum()))
print('ASR      : %.1f%%' % (100 * c.success.mean()))
print('mean perturb rate: %.1f%%' % (100 * c.perturbation_rate.mean()))
print('mean Jaccard     : %.3f' % c.similarity.mean())
"
```

Two denominators, both reported: `asr` (flips / attacked) and `asr_of_eligible`
(flips / all eligible, i.e. counting samples the model re‑read as benign as
non‑flips). Quote the first in the results table, the second in the appendix.

**Quote an interval, not a bare percentage.** The flip counts are 0–6, so
`asr` on its own overstates precision:

```powershell
./venv/Scripts/python.exe -c "
import pandas as pd
from src.attack_common import asr_interval
df = pd.read_csv('results/attack_results_char_qwen2.5-3b.csv')
c = df[df.counted == True]
ci = asr_interval(c.success.tolist())
print('ASR %.1f%% (95%% CI %.1f-%.1f%%, n=%d, flips=%d)'
      % (100 * ci['flips'] / ci['n'], 100 * ci['wilson_low'],
         100 * ci['wilson_high'], ci['n'], ci['flips']))
"
```

`src/summarize_attack.py` writes `ci95_low`/`ci95_high` (Wilson) and
`boot95_low`/`boot95_high` (percentile bootstrap) for every row. Quote the
**Wilson** bound when flips are 0: the bootstrap collapses to `[0, 0]`, which
would claim that a 0/188 row rules out any flips at all.

### Step 2.4: Check plausibility
- **mean perturbation rate** must stay ≤ 15% — the runner warns above it.
- **n_attacked < 10** is too small to call an ASR; the runner warns.
- ASR 0% means the model is robust to typos. Report it — do not tune the
  attack until a number appears.
- The per‑task breakdown (SMS vs email) is in the summary; they differ a lot.

## 🔄 Phase 3: Attack Engine 2 — Word‑Level

Same pipeline, different perturbation family: synonym swap, deletion,
duplication and word swap, under the same single 15% budget.

```powershell
./venv/Scripts/python.exe src/run_attack.py --model qwen2.5-3b --mode word --attempts 3
```

**Output:** `results/attack_results_word_<model>.csv` and
`results/asr_summary_word_<model>.txt`.

**Key differences from char‑level:**
- each edit changes meaning more (words, not glyphs), so the honest similarity
  floor has to be argued explicitly;
- `SYNONYMS` in `attack_common.py` is a small hand‑written map and the draw is
  **uniform at random**. This mode is a random word attack, not PWWS. The
  saliency-guided attack is a separate mode (Phase 6) — do not describe this one
  as saliency-guided in the paper.

## 🔀 Phase 4: Cross‑Model Transfer

### Step 4.1: Replay the stored perturbations on another model
```powershell
./venv/Scripts/python.exe src/run_transfer.py --target phi3.5-mini
```

No new attack is generated: every `perturbed_text` already stored in
`results/attack_results_*.csv` is re-sent, with the same prompt and temperature.
The rule that makes the number meaningful is in `src/transfer_common.py` — the
**target owns the denominator**: a perturbation transfers only if the target read
the original as malicious and the perturbed text as benign.

Add `--include-self` to run the faithfulness check in the same pass: replaying a
model's own perturbations must reproduce its single-model ASR exactly, and
`summarize_transfer.py` compares the diagonal against `attack_table.csv`,
printing one row per cell and exiting non-zero on any mismatch. If the diagonal
does not match, the off-diagonal cells cannot be trusted. The kernel passes this
flag for every target, so the check is never optional in a Kaggle run.

The transfer matrix must then be scored with the same `chat_verdict` call and
the same prompts; a transferred attack counts as a success only if the target
model called the ORIGINAL malicious and the PERTURBED benign in this run.

### Step 4.2: Build the matrix
```powershell
./venv/Scripts/python.exe src/summarize_transfer.py
```

Writes `results/transfer_matrix.csv` with two subsets per cell: `flipped_source`
(the classic matrix, small n) and `applied` (every perturbation applied, with the
target's caught originals as denominator). Quote the subset you mean; never mix
them in one table.

## 🔍 Phase 5: Saliency‑Guided Word Attack (PWWS)

The random word attack answers "does any edit break it". This phase answers
"which words carry the verdict", and it is a different attack, not a tuned
version of the random one.

### Step 5.1: The probability endpoint must be alive
```powershell
./venv/Scripts/python.exe src/run_saliency.py --model qwen2.5-3b --limit 3
```
The first line proves it: `verdict_probs OK (p_malicious=...)`. If instead it
exits with "the shim has no working /v1/verdict_probs endpoint", restart the shim
from the current `src/shim_colab.py` — do **not** fall back to random search and
keep the saliency label.

### Step 5.2: Full run
```powershell
./venv/Scripts/python.exe src/run_saliency.py --model qwen2.5-3b
```

`src/saliency_common.py` implements
$\phi = \alpha \tilde S_i + (1-\alpha) p_{i,w}$ with $\alpha = 0.5$ and
$\tilde S$ normalised to $[0,1]$. The normalisation is load-bearing: with raw
$S$ and $\alpha=0.5$ the score is a constant, and the greedy loop degenerates
into applying substitutions left to right. `tests/check_saliency.py` guards it.

Candidates come from a curated security lexicon plus WordNet synonyms ordered by
lemma frequency; multi-word replacements are excluded so the 15% budget counts
words. Each row stores `n_queries`, so the query cost is on the record.

**Output:** `results/attack_results_saliency_<model>.csv` (same schema as char
and word, so `summarize_attack.py` aggregates all three).

## 🛡️ Phase 6: Defence Probe (Training‑Free)

Runs on the perturbations that already exist — no new attack, no fine-tuning.

```powershell
./venv/Scripts/python.exe src/run_defense.py --model qwen2.5-3b
```

- **D1 normalisation**: NFKC, invisible/format characters stripped, Cyrillic and
  Greek homoglyphs folded back to ASCII, whitespace collapsed. It can only undo
  the mechanism of the character attack; expecting it to help against a word
  attack would be a category error, and the null result is worth reporting.
- **D2 matched‑FPR threshold**: `tau` is the largest value whose clean
  false‑positive rate does not exceed the baseline's own. This is the only honest
  way to report a threshold change.

The script also prints a re-derivation check: the probability route must agree
with the verdict each attack run stored. A mismatch means the shim is not
serving the same model, and the defence numbers are meaningless until that is
fixed.

**Output:** `results/defense_rows_<model>.csv`, `results/defense_summary.csv`.

## ⚠️ Important Notes & Constraints

1. **Temperature = 0 everywhere.** Deterministic verdicts only. No sampling variance.
2. **Prompt is fixed.** The same `build_messages()` is used for all models and all attacks. If a model does badly, that’s the result — not a bug in the prompt.
3. **Seed 42 for all data splits.** Reproducible across runs.
4. **Colab vs Local.** The `run_baseline.py` works with any OpenAI‑compatible endpoint. For Colab, use a tiny Flask/FastAPI shim that forwards to `transformers.pipeline(..., model=..., device=0)`.
5. **No fine‑tuning.** All experiments are zero‑shot / few‑shot‑free. The contribution is measuring fragility, not improving the model.
6. **Hardware limits.** Free T4 GPU → ~2–3 tokens/ms for 3B models. Keep `max_new_tokens=8` and `temperature=0` to stay under time limits.
